# Effective batch512 拒绝结论与机制诊断

日期：2026-10-04，Asia/Hong_Kong。原始证据位于 Git 忽略目录 `reports/batch512-experiment-20261004/`，未随本报告发布，获取方式见[证据说明](../experiment-evidence.zh-CN.md)。

## 冻结结论

**Effective batch512 rejected。** 三个独立训练 seed 全部 FAIL，按冻结协议跨 seed 判定为 REJECT。两个 Balanced 在每个 seed 的单侧上界均低于零，证据是显著退化，不只是未证明提升。不进入 final holdout，不加样本，不追加第四 seed，不改生产默认 batch256，也不自动启动 rescue。既有评测跟进任务已为 PAUSED。

本实验在 micro_batch=64 下将 accumulation 从 4 改为 8，effective batch 从 256 改为 512。拒绝的是该协议下的 batch512 方案，不是 accumulation=8；仓库默认为 micro_batch=32 × accumulation=8 = batch256。

## 机制诊断边界

本文将 `successful_steps × effective_batch / fresh_samples` 称为 sample-update ratio 或 replay sampling intensity，即 learner sample presentations per fresh sample，不与按 gradient updates / newly collected experience 定义的 replay ratio / UTD 混用。[Fedus 等，Definition 3](https://proceedings.mlr.press/v119/fedus20a/fedus20a.pdf) 的 replay ratio 按更新次数计；[RLlib 的 training_intensity](https://github.com/ray-project/ray/blob/master/rllib/algorithms/dqn/dqn.py) 则将 train batch size 纳入 replay 抽样与新增样本的比例，口径更接近本项目指标。

本实验没有将按更新次数计的 update-to-data ratio 提高一倍：每 seed 的 successful optimizer update 终点相同，fresh-data 配置与 collection credit 规则不变。实测阶段 fresh samples 在 seed43/44/45 分别相差 +3 / -1,954 / -1,598 行，约 1.43–1.44 亿行中的不到 0.002%，因此应说近乎相同，而不是逐行完全固定。翻倍的是每次 optimizer update 的 effective batch，以及阶段 learner sample presentations 相对 fresh samples 的强度。DouGPU 的 `fresh_samples` 只计完成牌局后写入的样本行，不直接等同于全部 environment interactions。

当前结果同时混合了至少两个潜在机制：更大 effective batch 引起的梯度噪声与 clipping/Adam 动态变化，以及单位 fresh data 对应的 replay sample presentations 增加。现有棋力结果不能区分二者；文献定义与经验结论也不能证明 DouGPU 的退化由其中任何一项导致。后续仅允许使用冻结 replay 与既有日志进行机制诊断；除非获得明确机制证据，否则不启动新的 batch512 rescue 训练。

所有窗口的 replay size 都为 65,536。梯度范数变化没有跨 seed 同向；更低的在线训练 loss 来自不同训练轨迹和采样分布，不能当作泛化改善或因果证据。

Treatment 三个 seed 的逐步 clipping 发生率均为 100%，平均 clip scale 分别为 0.06644、0.06871、0.08033。Baseline 仅有 cycle 平均 norm，无法恢复逐步 clipped fraction、clip scale 或 norm 方差；不能拿 `clip(mean norm)` 与 treatment 的 `mean clip scale` 比较。

混合 batch fork 后，旧 `cumulative_sample_update_ratio=U×512/C` 把 fork 之前的 batch256 更新也按 512 计数，不能使用。正确累计剂量为 `[U0×256+(U−U0)×512]/C`，三个 treatment 分别为 0.667926、0.668317、0.668066；对应 baseline 为约 0.5。阶段剂量才接近 2×，累计剂量不应宣称为 2×。原协议已登记该限制，本次没有修写历史日志。

源码流确认：`model.py` 在 accumulation 平均之后计算 norm 并 clipping；`replay.py` 按 effective batch 分角色有放回抽样；`train.py` 的 collection credit 每个成功更新消耗 `fresh_samples/updates_per_cycle`，不随 batch 成比例。因此本实验同时改变梯度统计和 replay sampling intensity，日志已直接确认阶段采样强度约翻倍，但尚未证明它是退化的原因。

## Frozen Replay 探针

从三个共同 4h parent 各抽 256 对 weighted batch256，共 768 对；参数、replay、Adam m/v/step 全部固定，每个 proposal 均从同一状态出发后丢弃。使用独立诊断 RNG，不生成新牌，不调用 actor，不保存续训状态。生产源码和 parent 只读挂载，容器网络关闭；没有改训练器或生产默认值。

原 `sample_losses` 提供逐 microbatch 梯度，探针按生产 arithmetic 平均得到 g256a / g256b，并取 g512=(g256a+g256b)/2。一步 Adam proposal 直接复用 `make_train_step`，不用另写优化器；逐对断言范数与生产 step metrics 一致、三个 proposal 都有限且只增加一步。相同 batch 的自检在 CPU 与 GPU 均通过，完整诊断在 LocalServer RTX 5070 完成并 exit=0。

| 44 | 15.7442 / 11.9956 | 0.7430 | 0.06887 / 0.08840 | 0.020926 / 0.020786 | 0.9544 | 0.2968 |

探针的两种 256 半批次与 512 平均梯度均 100% 触发 clipping。512 norm 下降约 23%–25%，clip scale 增大约 28%–31%，方向和同一 Adam state 下的一步 proposal 都确实改变。不能把“clipping 发生率相同”写成“clipping 没区别”，也不能据此宣称 clipping 已解释棋力退化。它与更高 replay sampling intensity 仍是两个需区分的机制。

本探针固定生产 micro_batch=64，保留每个半批次的两个 history groups，并补 PAD 至 512 来固定编译形状。g512 保留两个 256 抽样的原角色权重与分组，不是重新调用 native batch512 sampler；合并角色行数为 172/170/170，而 native512 为 171/171/170。因此它回答所要求的成对梯度平均问题，不声称逐位复现线上 batch512 的抽样、分桶或整个训练轨迹，也只覆盖共同 4h 状态。

入口为 `frozen_probe.py`（以仓库或冻结源码为 PYTHONPATH，`--selftest` 可单独运行）。`frozen-replay-output/` 保存每对读数与汇总；`verify_diagnostics.py` 复算全部汇总，核验远端/本地哈希、冻结输入 manifest、镜像与 exit 状态，结果为 `diagnostics-verification.json`。汇总 SHA256 `65dc008dc7e2d48c5c61f1646c2f72fec0d2376a9e9545fcbb3535df783c419e`。

## 后续限制

已完成结论冻结、既有日志复算和 frozen-replay 梯度探针。三层流程为 A：既有日志/accounting 复算；B：冻结状态下成对梯度与 Adam proposal 诊断；C：仅在 B 找到明确机制后才考虑 rescue。既有 A/B 结果保持原样，不回溯称为本次建议的预注册；任何新增诊断或实验的范围、机制判据与停止规则须在运行前另行冻结。

后续 A 应补齐 replay age distribution 与 nonfinite steps；B 应记录 `||g256a−g256b||²`，而不是只凭 grad_norm 推断噪声。在同一冻结状态、两个独立同分布半批次下，其期望的一半估计 batch256 梯度噪声的局部方差迹，不是自动得到全局有效 batch scale。既有每对 norm 和 cosine 足以按 `||gA||²+||gB||²−2||gA||||gB||cos(gA,gB)` 后算该读数；须标注为基于已保存浮点标量的事后推导，不能冒充预先记录的完整梯度测量，也无需重跑 probe。

C 的限制保持不变：若明确主要差异来自 clipping，才允许另行提出 clip-specific experiment；若 clipping 基本一致且主要差异是 sample-presentation intensity，才允许另行提出 dose-matched batch512；若两者都没有明显解释力，停止 batch512 方向，不继续调 LR/clip/replay 参数凑结果。当前 clipping 与采样强度都已发生变化，但尚未归因，不能据此自动选中任一 rescue。当前 REJECT 不因机制假说而撤销。

Batch 翻倍后，不可能同时固定 fresh data、optimizer update 数、total learner sample presentations 和 Adam trajectory。固定 updates 必然增加采样量；updates 减半虽保持 `512×U/2=256×U`，却改变 Adam 更新次数、momentum、second moment 与 weight decay 的轨迹。后续若采用这种方案，必须称为 dose-matched alternative algorithm，而不是纯粹隔离 batch size 的控制实验，并明确所固定的量。保持不加样本、不做第四 seed、不进入 final holdout、不修改默认 batch256。
